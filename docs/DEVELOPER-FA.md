# 🛠️ راهنمای توسعه‌دهنده — معماری و قانون کامنت‌نویسی

## معماری لایه‌ای

```text
UI (Sahand.App — WPF فارسی/RTL)
      │  فقط از طریق PartMeshFactory / ExportManager / ReportService
CLI (Sahand.Cli — همان هسته بدون UI)
      ▼
هندسه (Sahand.Geometry) ──► خروجی‌گیرها (Sahand.Exporters)
      ▼                              ▼
دامنه (Sahand.Core) ◄────── گزارش (Sahand.Reporting)
پارامترها/رزوه/اعتبارسنجی/کاتالوگ/پروژه/چاپ
```

قواعد معماری:

- **دامنه به UI/OS وابسته نیست** — روی Linux آزمون می‌شود؛ هر چیز Windows-خصوصی (مثل DPAPI) پشت اینترفیس (`ISecretProvider`) در لایهٔ App ایزوله است.
- **موتور هندسه مش تولید می‌کند، نه B-Rep** — مرز صادقانه: خروجی STEP فعال نیست چون از مش مثلثی ساخته نمی‌شود (منع سند ۴).
- **کلید watertight**: همهٔ پچ‌ها اندیس رأس مشترک دارند؛ درپوش‌ها با رأس‌های همان سطح ساخته می‌شوند (`RadialSurface.AddFanCap/AddRingCap`) و شبکهٔ زاویه‌ای با «زوایای ویژه» ساختارها را هم‌راستا می‌کند (`AngularGrid`).

## مدل ریاضی رزوه (خلاصهٔ قرارداد — سند ۷-۵)

- واحد پایه: **میلی‌متر**؛ اینچ فقط لایهٔ ورودی/نمایش.
- محور قطعه: **Z**؛ z=۰ روی سطح اتکا؛ سر پیچ در z منفی.
- سطح رزوه: `R(θ,z) = ρ(z − Δ(θ))` که `Δ(θ) = ±(lead/2π)·θ` (علامت = راست/چپ‌گرد) و `ρ` پروفیل تناوبی با دورهٔ **lead** (نه pitch) است.
- `pitch` فاصلهٔ دندانه‌های مجاور؛ `lead = pitch × starts`؛ هرگز یکی فرض نمی‌شوند.
- winding مش: نرمال بیرونی (قانون دست راست)؛ درپوش‌ها/حفره‌ها با جهت صریح ساخته می‌شوند.
- زاویه‌ها در مدل داده: **درجه**؛ رادیان فقط داخل توابع مثلثاتی.

## قانون کامنت‌نویسی (خلاصهٔ اجرایی سند ۷)

- کامنت‌ها **فارسیِ فنی** دربارهٔ «چرا» (تصمیم/قید/واحد/محدودیت) — نه بازگویی بدیهیات.
- هر API عمومی XML docs با `<summary>` و در صورت لزوم `<param>/<returns>/<remarks>` دارد.
- واحد در نام‌ها encode می‌شود (`NominalDiameterMm`, `PitchMm`, `AngleDegrees`).
- TODO فقط با شناسهٔ قابل‌پیگیری مجاز است (`TODO(SSND-123): …`).
- هیچ راز/شمارهٔ کارت/دادهٔ شخصی در کامنت/تست/لاگ نوشته نمی‌شود — با بازبینی و آزمون تضمین می‌شود.
- تولید XML docs در build روشن است (`GenerateDocumentationFile`).

## گسترش (نقاط توسعهٔ طراحی‌شده)

| برای افزودن | نقطهٔ توسعه |
|---|---|
| فرمت خروجی جدید | `IExporter`-گونه: افزودن کلاس exporter + ثبت در `ExportManager` و `ExportCapabilityMatrix` |
| خانوادهٔ رزوهٔ جدید با کاتالوگ | `ThreadCatalog.GetEntries` + پارامترهای پروفیل در `ThreadProfileFactory.GetFamilyParameters` |
| سر پیچ جدید | متد `BuildXxxHead` در `BoltBuilder` + قواعد `PartValidator` |
| هستهٔ B-Rep (STEP) | پروژهٔ جدا با کتابخانهٔ دارای مجوز؛ لایه‌های موجود از صفر تغییر نمی‌کنند |
| relay HTTPS به‌جای SMTP | پیاده‌سازی `IReportTransport` |

## آزمون‌ها

- ۱۱۳ آزمون xUnit؛ اجرای کامل: `dotnet test SahandScrewMaker.sln`.
- آزمون‌های SMTP با **سرور شبیه‌سازی‌شدهٔ درون‌پردازشی** کار می‌کنند (بدون شبکهٔ بیرونی).
- برای دسترسی آزمون به اجزای internal از `InternalsVisibleTo` استفاده شده (سند ۶-۱) — این دریچه در UI قابل‌تنظیم نیست.
