## ۲. بررسی امکان‌سنجی در محیط اجرای فعلی

- **محیط عامل:** Linux (بدون دسترسی به Windows). SDK نصب‌شده: **.NET 8.0.426 (LTS)** — این نسخه LTS پشتیبانی‌شده است و با الزام سند معماری سازگار است.
- **ساخت پروژهٔ WPF روی Linux:** با ویژگی `EnableWindowsTargeting=true` امکان build وجود دارد؛ اما **اجرای پنجرهٔ WPF و آزمون بصری آن روی این محیط ممکن نیست**. این محدودیت طبق سند آزمون، صریح و شفاف گزارش می‌شود؛ هیچ ادعای «آزمون Windows» مطرح نمی‌شود.
- **آزمون‌پذیری روی Linux:** تمام لایه‌های غیر-Windows (دامنه، هندسه، خروجی‌گیرها، صف گزارش، CLI) با xUnit روی همین ماشین اجرا و تأیید می‌شوند. آزمون‌های WPF به‌صورت «تأییدنشده» علامت می‌خورند.
- **شبکه:** فقط برای نصب SDK/NuGet در زمان توسعه استفاده می‌شود؛ خود برنامه هیچ دانلود زمانِ اجرا ندارد.

## ۴. برش تحویل (Vertical Slice) و ترتیب اجرا

سند مادر، شروع با «برش عمودی کوچک اما واقعی» را خواسته است:

1. **هستهٔ دامنه** (Sahand.Core): مدل پارامتریک، رزوه، واحد، اعتبارسنجی، پروژهٔ `.ssnd`، کاتالوگ
2. **موتور هندسه** (Sahand.Geometry): جاروب مارپیچ، جامدات دورانی، سازندهٔ پیچ/مهره/واشر/میل، اعتبارسنجی مش
3. **خروجی‌گیرها** (Sahand.Exporters): STL باینری/ASCII، OBJ، PLY، 3MF، GLB، DXF دوبعدی + خوانندهٔ round-trip
4. **گزارش و ایمیل** (Sahand.Reporting): صف محلی، redaction، SMTP امن
5. **CLI** (Sahand.Cli): تولید/خروجی/اعتبارسنجی headless
6. **رابط WPF** (Sahand.App): ۸ بخش سند ۲، راست‌چین، وزیرمتن، حمایت با کارت پوشیده
7. **تست‌ها + مستندات فارسی + گزارش تحویل صادقانه**

## ۷. ریسک‌ها و محدودیت‌های شناخته‌شده

1. **اجراهای Windows (WPF/DPAPI/نصب):** روی این محیط اجرا نمی‌شوند؛ کد جدا شده تا روی Windows بدون تغییر کامپایل شود و آزمون‌های منطق مشترک روی Linux اجرا شوند. DPAPI پشت اینترفیس `ISecretStore` ایزوله است.
2. **کیفیت مش رزوه:** اعتبارسنجی self-intersection کامل O(n²) است؛ نسخهٔ هیوریستیک (شبکهٔ فضایی) با برچسب صریح محدودیت ارائه می‌شود.
3. **دادهٔ استاندارد:** فقط مقادیر عمومی شناخته‌شده با برچسب منبع؛ ادعای انطباق رسمی نمی‌شود.
4. **هر فایل پس از ساخت، پیش از فایل بعدی کامیت و پوش می‌شود** (دستور کارفرما)؛ برخی کامیت‌های میانی ممکن است به‌تنهایی build کامل نباشند — کامیت پایانی هر پروژه نقطهٔ سبز build است.

## ۸. قراردادهای ثابت پروژه (که همهٔ کد باید رعایت کند)

- واحد پایهٔ هندسه: **میلی‌متر**؛ اینچ فقط لایهٔ نمایش/ورودی. تبدیل در مرزِ ورودی انجام و ثبت می‌شود.
- محور قطعه: **Z+** از سطح اتکا به سمت انتهای ساق؛ مبدا روی سطح اتکا در مرکز.
- زاویه‌ها در مدل داده: **درجه**؛ تبدیل به رادیان فقط داخل توابع مثلثاتی.
- `pitch` = فاصلهٔ محوری دندانه‌های مجاور؛ `lead = pitch × starts`؛ هرگز یکی فرض نمی‌شوند.
- جهت winding مثلث‌ها: **نرمال به بیرون جسم** (قانون دست راست).
- کامنت‌ها: فارسی، دربارهٔ دلیل/قید/واحد؛ API عمومی با XML docs فارسی.
- هیچ secret/شمارهٔ کارت در کد، کامنت، تست، log یا فایل پروژه نوشته نمی‌شود (شمارهٔ کارت فقط در صفحهٔ حمایتِ UI و به‌صورت پوشیده).
